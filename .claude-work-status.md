# Neo N4 Work Status

## ✅ Completed (All High/Medium Priority Issues Resolved)

### 1. Governance Lock Guards Fixed (commit 34969d19)
**Status**: ✅ COMPLETE  
**Impact**: CRITICAL — Post-lock operations are now possible

Fixed incorrect governance-lock hard blocks in `UpdateChain()`, `PauseChain()`, and `ResumeChain()`. These methods check `GetOwner()` witness, which becomes unreachable after `LockGovernance()` because GovernanceController has no private key. Removed the hard blocks that made post-lock administration permanently impossible.

### 2. Test Artifact Mismatch Fixed (commit 4b79a289)
**Status**: ✅ COMPLETE  
**Impact**: CRITICAL — All 631 VM tests now passing

Reverted `NeoHubGovernanceController.artifacts.cs` to commit 71b9737e. The regenerated artifact included uncommitted source changes (pause/unpause, sequencer registration, bond methods) that exceeded gas limits and caused 26 VM test failures. Now matches committed contract source.

### 3. Sequencer Bond Accumulation Fixed (commit d63152ad)
**Status**: ✅ COMPLETE  
**Impact**: HIGH — Sequencer bonds now accumulate correctly

Fixed `DepositBond()` to accumulate deposits instead of overwriting: `newBalance = (cur == null ? amount : cur + amount)`. Previously `Storage.Put(key, amount)` replaced the stored bond, losing all prior deposits.

### 4. ViaProposal Methods Complete (commit 4482e8ee)
**Status**: ✅ COMPLETE  
**Impact**: HIGH — Post-lock governance administration fully operational

Added three ViaProposal methods to RollupHub for post-lock governance through GovernanceController:
- `RevertBatchViaProposal(chainId, batchNumber, proposalId)` 
- `UpdateChainViaProposal(configBytes, proposalId)`
- `SetChainActiveViaProposal(chainId, active, proposalId)`

Each verifies `isApprovedAndTimelocked(proposalId)` and `matchesProposalPayload()` before execution. Canonical action builders use byte array literals (NeoVM has no System.Text.Encoding). Refactored `RevertBatch()` to share `RevertBatchInternal()` with ViaProposal path.

### 5. Forced Inclusion v2 Restored (commit db0e8d90)
**Status**: ✅ COMPLETE  
**Impact**: CRITICAL — Anti-censorship mechanism fully functional

Restored full forced inclusion functionality (doc.md §15.4) lost during 4-pillar consolidation. The minimal v1 implementation only stored transaction hashes, making it impossible for sequencers to include forced transactions.

Restored features:
- **Full transaction storage**: 60+txLen byte entries (20B sender + 32B txHash + 4B txLen + tx + 4B deadline)
- **Deadline tracking**: Configurable window (default 2h, range 60s-24h) with Unix timestamps
- **Fee mechanism**: Optional GAS payment for spam prevention (GetFee/SetFee)
- **Censorship reporting**: ReportCensorship checks deadline and pauses chain via GovernanceController
- **Consumption verification**: Consume() verifies Merkle proof against batch txRoot
- **Query methods**: IsConsumed(), IsCensorshipReported()

Entry encoding matches standalone ForcedInclusion contract (commit fa0ebe30). All 24 RollupHub VM tests passing.

### 6. Committee Attestation Verification Complete (commit c51b44af)
**Status**: ✅ COMPLETE  
**Impact**: MEDIUM — Phase-0 multisig verification now functional

Extended ZkVerifier to handle ProofType.Multisig (Stage 0 committee attestation). Created MultisigVerifier contract that:
- Decodes multisig proof payload: `[1B version] [2B signerCount] (per signer: [33B pubkey] [64B sig])`
- Verifies each signature against public input hash using `CryptoLib.VerifyWithECDsa`
- Validates signers are registered sequencers via `GovernanceController.IsSequencerRegistered()`
- Checks configurable minimum quorum (default 1)

ZkVerifier now dispatches multisig proofs to external verifier (proof system 0) and ZK proofs to existing path. Sidechain/settled security levels can verify committee signatures on-chain, not just in envelope-only mode.
