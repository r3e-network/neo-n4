### Commit 4482e8ee: ViaProposal governance methods ✓
Added three post-lock governance methods that route through GovernanceController:

1. **RevertBatchViaProposal**: Revert disputed batches via approved council proposal
2. **UpdateChainViaProposal**: Update chain configuration via approved council proposal
3. **SetChainActiveViaProposal**: Pause/resume chains via approved council proposal (replaces direct PauseChain/ResumeChain)

Each method:
- Verifies governance is locked
- Checks GovernanceController witness
- Validates proposal is approved + timelocked
- Asserts payload binding (prevents blank-check attacks)

Added canonical action builders (`Build*Action`) for off-chain tooling to construct proposal payloads. Refactored RevertBatch to share internal logic, eliminating duplication.

**Status**: Requires significant redesign work

The 4-pillar consolidation deleted `NeoHub.ForcedInclusion` contract and moved minimal queue logic into RollupHub. Critical features were lost:

**Missing from current RollupHub.EnqueueForcedTransaction:**

**Scope**: Large - requires:

**Recommendation**: Defer to dedicated forced-inclusion restoration task.

### 2. Committee Attestation Verification (MEDIUM)
**Status**: Requires new contract or significant ZkVerifier extension

RollupHub accepts three proof types:
- `ProofType.Multisig = 1` (committee attestation)
- `ProofType.Optimistic = 2`
- `ProofType.Zk = 3`

Current state: ZkVerifier only handles `ProofTypeZk = 3` and rejects multisig proofs at line 221. There is no separate MultisigVerifier contract.

**Options**:
1. Create new `NeoHub.MultisigVerifier` contract for committee attestation
2. Extend ZkVerifier to handle multisig envelope parsing (would require renaming to `UnifiedVerifier` or similar)
3. Implement multisig verification inline in RollupHub (breaks separation of concerns)

**Scope**: Medium-large - requires contract design decision + implementation.
